## D30 — README للعرض فقط، دون موقع (2026-10-08)

المستخدم طلب README منسقًا مثل مشاريعه الأخرى، مع صور Android الثماني التي أرسلها وروابط، والتنبيه أن مهامي تطبيق Native لـiOS وAndroid. تنسيق portfolio باستخدام الأصول الأصلية، مع شرح SwiftUI/SwiftData وCompose/Room وحالة كل منصة دون ادعاء جاهزية إنتاجية أو مزامنة Android. لا إنشاء موقع ولا نشر أو رفع GitHub في هذا checkpoint. النطاق ومعايير القبول في docs/design/README_SHOWCASE.md.


## D31 — استكمال تذكيرات Android ورفع العمل (2026-10-08)

المستخدم طلب استكمال التذكيرات وما يتعلق بها بعد نسخة العرض، ورفع كل التغييرات إلى GitHub. تفويض build/run للتحقق وارد صراحة في طلبه. تنفذ تذكيرات Android بـ AlarmManager وقناة وإذن notifications في السياق، ودقة exact اختيارية مع fallback معلن، دون schema migration أو تغيير التنقل. النطاق ومعايير القبول في docs/design/ANDROID_REMINDERS.md. دمج TaskFlow ينتظر تحديد Native مقابل Flutter لأن المشروع الحالي Native؛ أصل .riv النهائي وُجد وhash متطابق بين نسخه المحلية.


## D32 — استكمال المزامنة الشخصية على Android وتوافق iOS (2026-10-08)

بعد طلب استكمال التذكيرات وما معها ورفع العمل، نكمل A4 على Supabase القائم. الحساب والمزامنة اختياريان؛ Room مصدر الحقيقة المحلي، RPC واحد ذري owner-only مع LWW وحذف، backup قبل أول مزامنة، وجلسة Android Keystore. تصحيح الأجزاء المؤثرة من iOS ضروري لتشغيل المنصتين على نفس السحابة دون سحق بيانات أحدث. لا فريق أو realtime أو تحويل Flutter؛ دمج TaskFlow ينتظر تحديد المستخدم. معايير القبول والمراجع وخريطة الملفات في docs/design/ANDROID_CLOUD_SYNC.md.

D31 follow-through: شمل إصلاح iOS المرتبط بالتذكيرات المستقبلية وnearest-64 وتحديث المحتوى وفتح المهمة في RootTabs القائم. لا إعادة تصميم أو تجاوز للترحيب؛ قبول إشعارات iOS الفعلي يظل متتبعًا.

## D33 — مراجعة المستودع العام وحماية الإعداد المحلي (2026-10-08)

المستخدم أكد تحويل المستودع إلى Public وطلب إخفاء ما يلزم ورفع التصحيحات، دون إنشاء موقع. فُحص التاريخ المتاح كاملًا عند البداية: 19 commit و322 blob، دون العثور على credentials أو ملفات توقيع/إعداد حقيقي منشورة. لا تدوير مفاتيح أو إعادة كتابة للتاريخ دون دليل تسرب؛ المسارات ومعرفات البيئة معلومات تشغيل وليست أسرار صلاحيات. حُذفت التفاصيل غير اللازمة من التوثيق الحالي، وزيدت قواعد ignore، وفُعّل GitHub secret scanning وpush protection. launcher يقرأ مسارات الجهاز من البيئة أو local.properties المتجاهل، مع الحفاظ على تفضيل cache المحلي. لا تغيير في التطبيق أو بياناته أو قرارات بدء التشغيل. معايير القبول والملفات والفحوص في docs/project/PUBLIC_REPO_REVIEW_2026-10-08.md.
