## 1) نطاق C2

| البند | الوصف | ملاحظة |
|---|---|---|
| Apple Sign-In | زر «تسجيل عبر Apple» بجانب الإيميل | أفضل UX على iOS ومطلوب لو ننشر بالـ App Store مع طرف تسجيل ثالث |
| حل تعارض مُعلن | LWW على مستوى الصف موجود في C1 — C2 يضيف: تسجيل التعارضات (audit) + سياسة واضحة معلنة للمستخدم | لا merge على مستوى الحقول في C2 — تبسيط مقصود |
| Outbox حقيقي | بدل full snapshot: دفع التغييرات من آخر مزامنة فقط (updated_at > lastSync) + طوابير إعادة محاولة | يخفض البيانات المنقولة ويقلل اعتماد الاتصال |
| استمرارية المزامنة | مزامنة عند العودة للتطبيق من الخلفية (scenePhase) + بعد كل mutation بنافذة تأخير (debounce 5 ثوان) — لا زر فقط | |
| مؤشرات واجهة | حالة المزامنة في الرئيسية (شارة صغيرة على ☁️: تم/فشل/جاري) | لا انسحاب صامت |
| إعادة محاولة | backoff أُسّي (30s → 2m → 10m) مع سقف؛ الإخفاق يظهر في الواجهة | |
| سجل التشخيص | سجل أخطاء المزامنة (آخر 20) معروض في شاشة الحساب | يخدم دعم المستخدم |

## 2) خارج نطاق C2 (ثابت)

- التعاون/المشاركة (C3) — Realtime — مرفقات — تذكيرات من السيرفر — نسخة أندرويد.

## 3) القرارات التصميمية المقترحة

1. **حل التعارض**: LWW بـ updated_at (كما في C1) + صف التعارض يُسجل في جدول `conflict_log` (side table محلي وسحابي) — معلن للمستخدم كسياسة: «آخر تعديل يفوز».
2. **Tombstones**: TTL 30 يوم — tombstone أقدم من كده يتشال (اللاجئون النادرون يتعاملوا بإعادة إنشاء).
3. **Apple Sign-In**: عبر AuthSession بـ `client.auth.signInWithIdToken` — التكامل مع ASAuthorizationAppleIDProvider.
4. **الاختبارات**: مصفوفة جهازين (سيميوليتر + جهاز حقيقي أو سيميوليترين): تعديل متزامن، حذف متزامن، طيران (offline) لكل جهاز، ثم العودة.

## 4) تقدير الجهد

- Apple Sign-In: checkpoint واحد صغير.
- Outbox + ديبونس + مؤشرات: checkpoint أساسي (الأكبر).
- conflict_log + مصفوفة اختبار الجهازين: checkpoint مراجعة — **ينصح بمراجعة بموديل أقوى** أو مراجعة بشرية متأنية (كما سُجل في CLOUD_PLAN §9).
