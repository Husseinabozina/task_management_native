# FEATURE_SCOPE — V1

ثلاث حالات فقط: **معتمد** (سيُنفذ في V1) / **مقترح** (checkpoint مستقل لو طُلب) / **مؤجل** (خارج V1 الآن). لا تخلط الحالات.

## معتمد في V1

| الميزة | التعريف | شرط القبول |
|---|---|---|
| شاشة البداية | «لنبدأ» بتخطيط فيجما 101:100 وصورة تنظيم مهام بلا ذوات أرواح ونصوص فصحى (D26) — لأول تشغيل فقط ثم فتح مباشر للرئيسية | تظهر مرة واحدة؛ الزر ينتقل للرئيسية فعليًا |
| قائمة المهام | شاشة مهامي بتصميم فيجما 101:265: شريط أيام (أول عنصر «الكل» يعرض المتأخرة/اليوم/القادمة/بلا موعد) + chips الحالة — views على نفس البيانات لا مخازن مستقلة | تظهر المحفوظة فعليًا + حالة فارغة مفهومة؛ اختيار يوم يفلتر فعلًا |
| إنشاء مهمة | عنوان مطلوب، وصف اختياري، أولوية، تاريخ اختياري، مشروع اختياري | عنوان فارغ بعد trim يُرفض؛ العنصر يظهر بعد حفظ ناجح فقط |
| Quick-add سطري | صف «إضافة مهمة…» آخر كل قائمة: اكتب واضغط Enter بلا فتح محرر (بروح Notion) | إنشاء فوري بقيم افتراضية؛ النص لا يُفقد عند فشل الحفظ |
| تعديل مهمة | نفس المحرر على المهمة المحددة | التغيير يخص نفس id ويعيد القيمة المحفوظة |
| إتمام/إعادة فتح | تبديل الحالة بالاتجاهين | completedAt يُضبط/يُلغى في نفس العملية |
| مواعيد وتصنيف | dueDate يوم تقويمي اختياري (بلا ساعة) + تصنيف Today/Overdue/Upcoming بقاعدة واحدة معلنة | التصنيف متطابق في كل الشاشات، والموعد الغائب لا يدخل أي تصنيف |
| بحث وفلاتر | بحث بالعنوان case-insensitive فوري + فلترة بالحالة والأولوية — ✅ نُفذ (Checkpoint 10: حقل بحث + menu أولوية في شاشة مهامي) | no results يختلف عن القائمة الفارغة ويحافظ على الفلتر |
| مشاريع | تجميع اختياري تحت مشروع باسم + إيموجي + لون | حذف المشروع يسأل؛ مهامه تنتقل إلى «بدون مشروع»، لا حذف صامت |
| حذف مهمة | حذف بتأكيد | تأكيد صريح؛ لا Undo زائف بعد حذف نهائي |

## إضافات Notion المعتمدة (قرار D3)

1. **هوية المشروع**: إيموجي + لون من لوحة ثابتة يظهران في الصفوف والفلاتر وشاشة المشاريع.
2. **Quick-add سطري** في كل قائمة مهام — الإنشاء الأسرع، والمحرر الكامل للتقلية.
3. **وصف markdown-lite**: bold/italic، قوائم نقطية — يُدخل كنص ويعرض منسقًا (دعم المنصة الأصلي للـ markdown).

## مقترح (checkpoint مستقل لو طُلب)

Board view بمجموعات، templates للمشاريع، تثبيت مهام مهمة، tags متعددة على المهمة.

## مؤجل

سحابة/auth/فريق/مزامنة — تذكيرات — تكرار — drag & drop — مرفقات — شاشة Settings (الثيم يتبع النظام في V1، قرار D4) — onboarding — widgets — مسار Android.

## خارج النطاق عمدًا في V1

- لا تسجيل دخول ولا شاشة Login.
- لا onboarding ولا splash مصطنع.
- لا زر ولا عنصر واجهة بلا سلوك حقيقي منفذ.

## أندرويد — نسخة العرض المحلية (D27، 2026-10-07)

النطاق الحالي المضاف: إصلاح A1 وتوصيل Room؛ ترحيب مرة واحدة؛ الرئيسية والمهام والتقويم والمشاريع؛ البحث وفلاتر اليوم والحالة والأولوية والمشروع؛ إضافة سريعة؛ تفاصيل Markdown بسيط ومحرر كامل مع التثبيت؛ إنشاء مشروع وحذفه مع الاحتفاظ بمهامه. تُستخدم الفصحى وصورة D26 وخطوط وألوان وأصول التصميم المحلي. التذكيرات والمزامنة مؤجلتان على أندرويد. لا إنشاء لبيانات تجريبية تلقائيًا. الشروط التفصيلية في `docs/design/ANDROID_PRESENTATION_PLAN.md`.

## أندرويد — بيانات العرض وطريقة التشغيل (D29، 2026-10-07)

بطلب صريح لاحق من المستخدم أُضيفت 4 مشاريع و16 مهمة وهمية للتصوير إلى الهاتف المتصل. الإدراج الصريح فقط في debug، دون تعديل الموجود أو تكرار المعرفات أو إعادة المحذوف؛ لا seed عند التشغيل العادي. ملف android/run-on-device.command يبني ويثبت ويحافظ على البيانات ويفتح التطبيق. الفتح اليومي من أيقونة «مهامي» دون الكمبيوتر. النطاق والتحقق في docs/design/ANDROID_DEMO_DATA.md؛ هذا توسيع مفوض لنطاق D27 السابق.

## أندرويد — التذكيرات (D31، 2026-10-08)

بطلب صريح لاحق استكمال التذكيرات: موعد اختياري كامل، إذن إشعارات عند التفعيل، جدولة محلية قابلة للاستعادة والإلغاء مع دورة حياة المهمة، وفتح تفاصيل المهمة من الإشعار. الدقة الخاصة اختيارية مع حالة تأخير معلنة دونها. معايير القبول في docs/design/ANDROID_REMINDERS.md؛ تلغي هذه الموافقة تأجيل A3 السابق.

## أندرويد — المزامنة الشخصية (D32، 2026-10-08)

استكمال A4 بطلب المستخدم اللاحق: حساب اختياري ومزامنة يدوية مع Supabase القائم، backup قبل أول مزامنة، LWW وآثار حذف ومعاملة ذرية، دون تعطيل العمل المحلي. تصحيح توافق iOS المشترك ضمن النطاق. لا فريق أو realtime. المعايير في docs/design/ANDROID_CLOUD_SYNC.md؛ يحل محل تأجيل A4 السابق.
