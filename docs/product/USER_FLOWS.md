# USER_FLOWS — الرحلات الأساسية

نص بسيط قبل أي أسماء كلاسات. كل رحلة تُقاس على النسخة التي يجربها المستخدم بنفسه.

## 1. إنشاء

1. أفتح التطبيق → أرى قائمة مهامي، أو حالة فارغة توضح أول فعل مفيد.
2. أضغط صف «إضافة مهمة…» آخر القائمة → أكتب العنوان → Enter.
3. المهمة تُحفظ محليًا وتظهر فورًا بترتيبها الصحيح.
4. أفتح المحرر: أضيف وصفًا/أولوية/تاريخًا/مشروعًا → Save → القائمة تعكس القيمة المحفوظة.

حالات: عنوان فارغ → رسالة ولا حفظ. فشل حفظ → رسالة تظهر والنص يبقى في الحقل.

## 2. إتمام

1. مهمة نشطة → أضغط دائرة الإتمام → تنتقل لحالة مكتملة بشكل واضح ومختلف.
2. completedAt يُسجَّل. من فلتر «النشطة» تختفي؛ في «الكل» تظهر مكتملة.
3. إعادة الفتح: نفس الدائرة → تعود نشطة وcompletedAt يُلغى.

## 3. تنظيم

1. أكتب في البحث → القائمة تنقص فوريًا (عنوان فقط، بلا حساسية لحالة الأحرف).
2. لا نتيجة → شاشة no results تحافظ على البحث وتتيح مسحه بضغطة.
3. أفتح مهمة → أغير الموعد/الأولوية/المشروع → Save.
4. أرجع للقائمة: التصنيف (Today/Overdue/Upcoming) اتحدث بقاعدة واحدة ثابتة.
5. أفتح تبويب المشاريع → مشروع بالإيموجي واللون → قائمة مهامه مصفى عليها بنفس المكونات.

## قواعد متقاطعة في كل رحلة

- لا زر double-submit أثناء الحفظ.
- كل عنصر يظهر للمستخدم محفوظ فعليًا، لا نسخة ذاكرة مؤقتة تختفي.
- الفشل يظهر للمستخدم برسالة مفهومة ولا يمسح draft.
